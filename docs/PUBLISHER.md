# 博客发布器

双击仓库根目录的 **打开博客发布器.cmd**，浏览器会打开本机发布窗口。服务仅在本机 `127.0.0.1:3210` 运行，不需要启动 Codex。

## 发文章 / Wiki

1. 选择或拖入 `.md`、`.markdown`、`.docx`、`.txt` 文件。
2. 选择「文章」或「Wiki 知识库」，选择分类；文章可设置年份、语种、文体，Wiki 可输入或选择分组。
3. 标题自动从文档读取，可直接修改。
4. 查看预览，然后点击「发布并推送 GitHub」。

「保存到博客」只写本机文件，不提交、不推送。未推送的内容会留在发布记录中，点击「推送 GitHub」或「重试推送」即可继续。请推送前一篇已保存内容后再保存同一位置的下一篇，以保持目录索引一致。

GitHub 收到推送后由 Cloudflare 部署；发布器不会把 GitHub 推送成功当成网站已经部署完成。

## Word 字体

读取 OOXML 的文档默认字体、主题字体、段落样式继承、字符样式及局部字体，为中西文分别保留字体声明，支持文章和 Wiki。Word 内嵌图片随内容保存。字体文件不会自动上传；读者设备缺少字体时浏览器使用后备字体，Word 的页面分页与网页不完全相同。

建议 Word 用「标题」样式或第一个非空段落写文章标题。文件内文字不作改写，桌面原文件不作修改。

## Markdown / LaTeX

支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。文章由 Pandoc 保留公式并用 KaTeX 显示，Wiki 延用现有 Markdown/KaTeX 流程。代码块与行内代码保持字面内容。公式错误或组件下载失败时保留 LaTeX 原文。

正文中引用的本地图片，需要用「添加配图」一起选择；例如 `![说明](images/photo.png)` 对应选择 `photo.png`。图片保存到 `assets/published/`。同名的不同图片请先重命名，以免无法判断对应关系。远程图片链接继续使用原链接。

文件建议 UTF-8 编码。`.doc`、PDF 暂不支持，先转换为 `.docx` 或 Markdown。

## 程序与 Git

- Node.js 24 或以上、Pandoc、Python 3、Git。当前电脑已有；Python 可自动发现 Codex 随附运行时，不依赖打开 Codex。
- 「本机设置」可修改 Pandoc / Python 的完整程序路径。
- 沿用 Git 已保存的 GitHub 登录；身份未配置、认证过期、远端有冲突时显示 Git 原因。请先解决原因再重试，工具不会强推或自动解决冲突。
- 自动提交只包含本次文章 / Wiki、配图及对应目录索引。暂存区有其他修改时会停止；本次文件保存后又被外部修改时也会停止。
- 此仓库已有自动推送 hook；发布器的提交会停用该 hook，由界面显式推送，以免「保存」时意外发布。
- 本机记录和程序日志在 `.publisher-state/`，已忽略，不上传 GitHub。移动博客文件夹时应保留该目录，以便继续未完成的推送。
