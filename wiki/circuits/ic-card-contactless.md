# 为什么 IC 卡不用接触就能更新余额和权限

> **核心问题：** 校园卡、公交卡明明没有电池，也没插电，为什么往读卡器上一贴，余额就能被改写、门禁权限就能被更新？"隔空"完成读写，能量和数据分别是从哪儿来的？

这个问题其实拆成两半：**卡怎么活过来的**（供能），和**数据怎么写进去的**（通信+安全）。下面逐层展开。

## 先破除一个直觉：卡不是"死"的

大多数人以为 IC 卡里面存着余额，读卡器"读取"一下就完事。实际上非接触 IC 卡（比如校园卡、公交卡）在工作时是**一台短暂存活的小型计算机**：

- 不平放时，卡里的芯片完全断电，没有电池，纯纯一块死 silicon；
- 靠近读卡器的瞬间，芯片被"唤醒"，开始运行内部程序、执行加密运算、读写存储区；
- 离开读卡器，芯片立刻断电，状态全部丢失——只有存储区里的数据留了下来。

所以"贴卡"那 0.1~0.3 秒里，实际上发生了一次完整的**上电→鉴权→读写→断电**流程。

## 能量从哪来：电磁感应

这是高中物理知识的实战版。

卡内部其实就两部分：**一个线圈（天线）+ 一块芯片**，线圈通常是蚀刻在卡里的铜箔，绕好几圈，肉眼仔细看卡片边缘能隐约看到。

读卡器持续向外发射 **13.56 MHz** 的电磁波（这是 ISO/IEC 14443 标准规定的频段，NFC 也是这个频段）。当卡靠近时，交变磁场穿过卡里的线圈，根据法拉第电磁感应定律：

$$\mathcal{E} = -N\frac{d\Phi}{dt}$$

线圈上感应出电动势，经过芯片内部的整流、稳压电路后，得到约 1~2 V 的电源，足够驱动芯片工作几十毫秒。这个技术叫**电感耦合**，和无线充电的 Qi 协议是同一个原理，只是功率更小、频率固定。

顺带一提：为什么卡要"贴"而不能隔太远？因为电感耦合的能量随距离衰减极快（近场，大致与距离三次方成反比），一般超过 10 cm 就采不到足够的能量了。这也是为什么刷交通卡基本要贴着读卡区。

> 有些场景用的是另一种 RFID——UHF 频段（860~960 MHz），靠电磁波反射供电，读写距离能到几米，比如快递驿站扫条码一样批量读标签、ETC 过站。频段和耦合方式不同，但"读写器供能"的核心思想一样。

## 数据怎么传：负载调制

芯片有了电，还要能和读卡器"说话"。方向是反过来的——读卡器一直在发 13.56 MHz 载波，卡并不产生自己的信号，而是用**负载调制（load modulation）**：芯片在内部的负载电阻上"通、断、通、断"地切换，这会反过来影响读卡器线圈上的电流波形。读卡器检测到自家波形的细微变化，就解读出了卡发来的数据（0 和 1）。

打个比方：读卡器是一直在喊话的人，卡不能喊，只能通过在对方话筒前"举牌子、放牌子"来回应。整个握手、鉴权、读写命令，都是靠这套机制一来一回完成的。

## 写余额不是"写个数字"：分区存储与鉴权

现在到核心问题了：为什么余额、门禁权限能被更新，而且不会被随便一个 POS 机改写？

以常见的 CPU 卡（现在校园卡、银行卡、公交卡主力都是 CPU 卡）为例，卡里的存储被划分成很多**扇区/文件**，每个扇区有自己的访问密钥（Key A / Key B），并且定义了严格的**访问条件**。以门禁卡为例，"允许进入 A 楼"就是某个扇区里的一个字节被写成了 `0x01`，读卡器读到这个值就开门；改成 `0x00` 权限就被取消。余额同理，通常是一个带校验格式的数值区。

改这些数据的流程不是"直接写"，而是：

1. **双向鉴权。** 读卡器先证明自己有密钥。经典做法是 Challenge-Response：读卡器发一个随机数，卡用密钥算出密文回过去，读卡器验证正确（同时卡也反向验证读卡器，防止假读卡器）。密钥存在读卡器/PSAM 安全模块里，而不是明文写在卡上。
2. **加密命令。** 鉴权通过后，"余额 +100"这条命令本身也是加密传输的，防止空中截获后重放。
3. **原子更新。** 卡内程序执行完后写回存储，同时更新同区的校验值和计数器（value block 机制），防止余额被复制、回滚。
4. **交易记录。** 更讲究的卡（比如银行）还会要求外部系统做双重记账，卡内余额只是缓存，真正的账本在后台服务器上。

## 为什么安全，以及曾经哪里不安全

这套系统的攻防历史很有意思：

- **Mifare Classic**（早期地铁卡大量使用）的加密算法 Crypto-1 是厂商私藏的"算法靠保密"典型，2008 年被彻底逆向，任何人都能用几十块钱的 PN532 模块克隆一张卡。这也是为什么"门禁卡可以被某宝复制"在那个年代是真的。
- **现在的趋势是 CPU 卡**：卡里有一块真正运行安全操作系统（Java Card 等）的微控制器，加密算法是公开的 AES/3DES/国密 SM 系列，密钥长度足够，且密钥永不出卡。想破解就得攻击算法本身或者物理侧信道（功耗分析之类），门槛高了一个数量级。
- 密码学的一条铁律在这里体现得很彻底：**安全只能建立在密钥上，不能建立在"算法保密"上**（Kerckhoffs 原则）。

所以"权限被更新"的本质是：一台有密钥授权的读卡器，在电磁感应供能的短暂窗口里，和卡完成了一次加密会话，改写了卡上某个受保护存储区的字节。

## 你的手机 NFC 为什么也能当卡用

手机模拟门禁卡/交通卡，本质是把上面那个"线圈+芯片"换成了手机里的 NFC 控制器 + 安全元件（SE）或宿主卡（HCE）。手机通电，安全元件里保管着卡的密钥和分区数据；贴读卡器时，NFC 控制器在天线被 13.56 MHz 载波"叫醒"（低功率下卡模拟模式，卡模拟不需要手机电池给主芯片供电那么高功率）。在读卡器眼里，你和一张真卡没有任何区别。

反过来，手机读卡（比如读校园卡余额）就是手机临时当了那个"发 13.56 MHz 电磁波 + 检测负载调制"的读写器。

## 小结

| 问题 | 答案 |
| --- | --- |
| 卡没电池，电哪来的？ | 读卡器 13.56 MHz 交变磁场 → 线圈感应电动势 → 整流稳压 |
| 数据怎么回传？ | 负载调制，影响读卡器自家载波波形 |
| 余额/权限怎么改？ | 扇区存储 + 双向密钥鉴权 + 加密写命令 |
| 为什么不怕被乱改？ | 密钥在授权读卡器/安全模块里；CPU 卡算法公开但密钥保密 |

一句话版本：**非接触 IC 卡是一台只在磁场里活零点几秒的微型加密计算机，"贴卡"的动作其实是给它上电、开机、执行一次安全的写操作、然后关机。**
