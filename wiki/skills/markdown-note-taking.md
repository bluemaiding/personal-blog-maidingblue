# 如何用 Markdown 记笔记

> **核心问题：** 用 Notion 搭了漂亮的数据库，用语雀剪藏了几百篇文章，半年后想找一个知识点，发现要先想起来"我当时放在哪个板块哪个页面"——笔记越记越多，越来越像垃圾场。纯文本的 Markdown 凭什么能解决这个问题？怎么用它搭一套记得快、找得到的笔记系统？

先说结论：Markdown 解决的不是"格式"问题，而是三个更根本的问题——**写得快、存得久、连得上**。下面按这三条展开。

## 为什么是纯文本：你在给十年后的自己存笔记

Word 文档、Notion 页面都是**私有格式**：软件倒了、会员断了、导出受限，你的笔记就被扣为人质。Markdown 文件本质是 `.txt` 加了约定俗成的符号，这意味着：

- **任何编辑器都能打开**——记事本、VS Code、手机上的随便什么 App；
- **任何搜索工具都能搜**——`grep` 一下全盘命中，不依赖 App 的搜索框；
- **能用 Git 管版本**——每次修改有记录、可回滚、跨设备同步白嫖 GitHub；
- **程序能处理它**——比如你这个博客的 wiki 就是用脚本扫描 `.md` 文件自动生成的目录，笔记即数据。

十年后再能打开今天笔记的格式，大概率只有纯文本。记笔记第一件事是选**容器**，Markdown 赢在容器不绑架内容。

## 语法：五个够用了

Markdown 语法全学会也不难，但日常笔记高频用到的就五个，剩下按需查：

**层级标题**——笔记的骨架：

```markdown
# 信号与系统复习          <- 一个文件最多一个
## 第三章 傅里叶变换
### 帕塞瓦尔定理
```

**列表和任务**——清单、步骤、待办：

```markdown
- 重点：频谱物理意义
- [ ] 课后题 3.5 未做
- [x] 往年卷 2024 已刷
```

**代码块**——不只放代码，公式推导、命令、表格数据都可以用它保持原样：

````markdown
```bash
npm install
```
````

**表格**——对比类知识神器：

```markdown
| 性质 | FT | DTFT | DFT |
| --- | --- | --- | --- |
| 时域 | 连续 | 离散 | 离散 |
```

**引用和加粗**——划重点：`**结论**`、`> 老师原话`。

公式方面，多数 Markdown 环境（包括本博客 wiki）支持 LaTeX：行内 $\omega_0 = 2\pi f_0$，独立成行放 `$$...$$`。理工科笔记这点很关键，纯文本党遇到公式有两条路：转 LaTeX 或者干脆贴图，前者可搜索、后者快——建议默认 LaTeX，推导草稿允许截图。

## 结构：一文件一主题，目录做书架而不是迷宫

新手最容易把 Markdown 记成"一个巨型文件装一门课"，三个月后就再也翻不动了。推荐结构：

**一个文件只写一个主题**，粒度参考：一次课、一个概念、一个 bug 复盘。文件名带关键词：`帕塞瓦尔定理.md` 而不是 `第三章笔记.md`——因为未来你搜索时记住的是概念名，不是章节号。

**目录只分两层**，用来当"书架"：

```
notes/
├── 信号与系统/
│   ├── 帕塞瓦尔定理.md
│   └── 采样定理.md
├── 数电/
└── 工具/
    └── git-常用命令.md
```

层级分类的致命伤是"一个笔记属于哪个分类"经常有二义性，所以**跨分类的聚合交给标签**：文件末尾写 `tags: 期末, 重点`，或者按 Obsidian 的 frontmatter 格式放在文件开头。同一个知识点可以同时属于"期末"和"重点"，不需要纠结。

**再加一个"入口页"**：每个大类放一个 `MOC.md`（Map of Content），里面只写链接清单——"复习从这里进"。目录负责存在，入口页负责指路。

## 连接：笔记系统的真正价值

孤立笔记的价值是"存档"，链接起来的笔记才有"复利"。Markdown 里链接成本极低：

```markdown
傅里叶变换的时域卷积对应频域[[相乘]]，见 [[采样定理]] 里的混叠解释。
```

规律是：**记新笔记时，问自己"它和我记过的哪条笔记有关？"** 有就顺手埋一个链接。一年后你会得到一个网，而不是一个堆。这也是 Obsidian 这类双链笔记工具火的原因——但工具只是载体，习惯才是本体：没有"主动建链接"的意识，用什么软件记的最后都是坟场。

配套的维护动作：

- **每周花 10 分钟"回链"**：翻最近的新笔记，给旧笔记补一句"这个也用于了 XXX"。网状结构是养出来的，不是设计出来的。
- **写"面向问题"的标题**：`为什么DFT会有频谱泄漏.md` 比 `第5章笔记.md` 好一百倍——本博客 wiki 就是照这个思路组织的，标题即问题，答案在正文。
- **定期问"这条还活着吗"**：删掉不再需要的笔记和删文件一样轻松，这是纯文本的自由。

## 工具链推荐

按投入程度三档：

1. **起步（0 学习成本）**：VS Code + Markdown All in One 插件，写、预览（`Ctrl+K V`）一体，文件放本地。
2. **主力（推荐）**：**Obsidian**——免费、本地纯文本文件、双链和标签原生支持、插件生态大。你的笔记始终是普通 `.md` 文件，哪天弃用 Obsidian 也不损失什么，这是它和 Notion 最本质的区别。
3. **自动化（进阶）**：笔记文件夹直接做成 Git 仓库，推送到 GitHub 私有仓库 = 免费版本管理 + 备份 + 多设备同步；进一步可以像这个博客一样，写脚本从 frontmatter 自动生成目录页。

## 小结

Markdown 记笔记的正确姿势，一句话版本：**用纯文本保证笔记"不死"，用"一文件一问题"保证可检索，用链接和标签把孤岛连成大陆。**

格式永远只是手段。真正决定笔记系统是资产还是垃圾堆的，是你在记下的那一刻有没有想过——未来的自己会怎么找回它。
